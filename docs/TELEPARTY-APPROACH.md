# แนวทางแบบ Teleparty บน Netflaz

เอกสารนี้อธิบายว่า "ดูด้วยกันแบบ Teleparty" ทำงานยังไง, Netflaz ทำซ้ำหลักการนั้น
อย่างถูกกฎหมายได้แค่ไหน, และเส้นที่เราเลือกไม่ข้าม

## Teleparty ทำงานยังไงจริงๆ

Teleparty (เดิมชื่อ Netflix Party) เป็น **ส่วนขยายเบราว์เซอร์** ไม่ใช่เครื่องเล่นวิดีโอ
ของตัวเอง หลักการคือ:

1. ผู้ชมแต่ละคน **ล็อกอินบัญชีตัวเอง** แล้วเปิดเครื่องเล่นทางการของบริการนั้นๆ
   (Netflix/Disney+/ฯลฯ) ในเบราว์เซอร์ของตัวเอง
2. ส่วนขยายฉีด content script เข้าไปในหน้านั้น (same-origin) ไปเกาะ element
   `<video>` ของหน้าเว็บทางการ
3. อ่านเหตุการณ์ `play` / `pause` / `seeked` และค่า `currentTime` แล้วส่งให้เพื่อน
   ในห้องผ่านเซิร์ฟเวอร์ของ Teleparty เมื่อได้รับเหตุการณ์จากคนอื่นก็เรียก
   `video.play() / pause()` และตั้ง `currentTime` ให้ตรงกัน
4. เพิ่มแถบแชตข้างๆ

**สิ่งที่ Teleparty ไม่ทำ:** ไม่ถอด DRM, ไม่เรียก API ลับ, ไม่เก็บรหัสผ่านใคร —
มันแค่ "สังเกตและสั่ง" `<video>` บนหน้าที่ผู้ใช้เปิดเองด้วยสิทธิ์ของผู้ใช้เอง

## Netflaz ทำซ้ำหลักการนี้ตรงไหน

โหมด **Co-Watch (เว็บ)** ในแอป (`WebCoWatchViewModel` + `injectedJS`) ทำแบบเดียวกัน
เป๊ะ แต่อยู่ใน `WKWebView` ของเราเอง:

- `WKUserScript` ถูกฉีดเข้าทุกหน้า ไปเกาะ `<video>` ตัวแรก
- ส่งเหตุการณ์ขึ้น native ผ่าน `window.webkit.messageHandlers.coWatch`
- native กระจายเหตุการณ์ด้วยโปรโตคอล `PartyMessage` ผ่าน WebSocket server ตัวเดิม
- ฝั่งรับเรียก `window.__coWatchApply(type, time)` เพื่อสั่ง `<video>` ให้ตรงกัน
- โฮสต์ส่ง heartbeat ทุก 2 วิ ให้ผู้ชมแก้ drift

นี่คือกลไกเดียวกับที่หน้า `WatchPartyViewModel` ทำกับ `AVPlayer` — ต่างแค่ว่าแหล่ง
วิดีโออยู่ในหน้าเว็บ

## ทำไมถึงชี้ไปที่ Netflix ตรงๆ ไม่ได้

1. **Netflix บล็อกการฝัง** — เครื่องเล่นเว็บของ Netflix ตรวจสภาพแวดล้อมและ EME/DRM
   แล้วปฏิเสธการเล่นใน `WKWebView`/เว็บวิวของแอปอื่น ในทางปฏิบัติวิดีโอจะไม่เล่น
2. **ผิด ToS** — การฝังและฉีดสคริปต์ควบคุมเว็บไซต์ Netflix เข้าข่าย "เข้าถึง/ดัดแปลง
   บริการโดยไม่ได้รับอนุญาต" แม้จะเป็นบัญชีผู้ใช้เองและไม่แตะ DRM ก็ตาม
3. **iOS เนทีฟคุมแอป Netflix ไม่ได้** — แอปภายนอกสั่ง play/pause ในแอป Netflix ไม่ได้

เราจึงทำกลไก Co-Watch ให้เป็นแบบ **ทั่วไป** (ใช้กับสื่อเปิด/เว็บที่ฝังได้) เป็นตัว
พิสูจน์หลักการ ไม่ได้ทำ scraper เจาะ Netflix โดยเฉพาะ

## สะพานเชื่อม Netflix ที่ "ถูกต้อง"

- **Deep link**: ปุ่ม "ค้นหาใน Netflix" เปิดแอป Netflix ทางการของผู้ใช้
  (`nflx://…/search?q=` หรือเว็บ) — ไม่มีล็อกอินผ่านเรา ไม่มี API ไม่มี DRM
- **สิ่งที่ควรเสนอ Netflix จริง**: ขอให้ Netflix เปิด **API สำหรับ co-watching**
  หรือรองรับ **Apple SharePlay (GroupActivities)** ซึ่งเป็นทางเดียวที่แอป/บริการ
  จะ sync การเล่นข้ามบัญชีได้อย่างเป๊ะและถูกต้อง — ต้องมาจากฝั่ง Netflix เอง

สรุป: Netflaz สาธิต "กลไก Teleparty" ได้ครบและถูกกฎหมายบนเนื้อหาที่ฝังได้ ส่วนการ
เอาไปใช้กับ Netflix จริงต้องรอความร่วมมือจาก Netflix (API/SharePlay) ซึ่งคือสิ่งที่
นำไปเสนอได้
